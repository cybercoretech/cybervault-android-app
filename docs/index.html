01 / What it does

A vault that
stays put.

Everything a phone vault needs, nothing that phones home. Built with the same Rust code as the desktop app, so there is one implementation of the format and the crypto — not a Kotlin rewrite.

◆ OFFLINE

NO INTERNET PERMISSION

The APK doesn't request network access at all, and CI fails the build if it ever does. Nothing to leak to, nothing to sync behind your back.

◆ ONE FORMAT

DESKTOP-COMPATIBLE

Export the encrypted vault file and open it in the desktop TUI, or import a desktop vault on the phone. Tested end to end: the desktop code reads what the phone writes.

◆ KEYSMITH INSIDE

GENERATE IN PLACE

Random passwords (8–64 chars, pick your sets, drop look-alikes) or EFF diceware passphrases (3–12 words), with a live entropy meter. One tap to use it.

◆ LOCKDOWN

NO SCREENSHOTS

FLAG_SECURE blocks screenshots, screen recording and the recent-apps thumbnail. Android backups and device transfer are disabled.

◆ CLIPBOARD

SENSITIVE + SELF-CLEARING

Copied secrets are flagged sensitive (keyboards and previews hide them) and wiped from the clipboard after 30 seconds, or on lock.

◆ AUTO-LOCK

KEYS LEAVE MEMORY

Locks after 60 s in the background or on demand. Locking drops the decrypted data and the password; the Rust side zeroizes them.

02 / Under the hood

Password in.
Ciphertext out.

The vault is one file in the app's private storage. Every save re-derives the key with a fresh salt and nonce and writes through a temp file, so a crash can't leave a half-written vault.

DERIVE

Master password + 16-byte random salt → Argon2id → 256-bit key.

SEAL

Entries as JSON → ChaCha20-Poly1305 with a fresh 12-byte nonce. The tag catches any tampering.

WRITE

Temp file → atomic rename. Mode 0600 inside a 0700 app-private directory.

FORGET

On lock, the decrypted entries and the password are dropped and zeroized.

HONEST LIMITS
  • Forget the master password and the vault is gone. There is no recovery, by design.
  • A compromised phone (root, malware with accessibility access) can read what you can read once unlocked.
  • Kotlin strings holding a revealed secret can't be wiped like Rust memory; the app keeps them short-lived.
  • Not yet: Android Autofill and biometric quick-unlock (planned for 0.2), sync through Holodrive (later).

05 / Install

Four ways
in.

The easiest is the Cybercore F-Droid repository (automatic updates). Every release is a signed APK with a published SHA-256. Android only accepts updates signed with the same CyberVault release key.

1 · FROM YOUR COMPUTER (ADB) 
# phone on USB with USB debugging on
curl -fsSL https://cybercoretech.github.io/cybervault-android-app/install.sh | sh

# or read it first
curl -fsSLO https://cybercoretech.github.io/cybervault-android-app/install.sh
less install.sh && sh install.sh
  • Downloads the latest release, checks its SHA-256, then runs adb install.
  • Refuses to pick a device if more than one is connected; set ANDROID_SERIAL.
2 · OBTAINIUM (AUTO-UPDATES) 
https://github.com/cybercoretech/cybervault-android-app
3 · MANUAL
  • Download cybervault.apk from the latest release on the phone and open it.
  • Verify: sha256sum --check cybervault.apk.sha256
  • Signing cert SHA-256: 9dfa3699b793ad16af999b2fbe99b4b13ee26f8014705cc661521ee2b15e52cb
  • F-Droid (auto-updates): add the Cybercore F-Droid repository and install CyberVault from there.
